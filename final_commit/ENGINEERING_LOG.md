## 1. Bug Registry

### BUG-001: Mode 15 Dither Payload Desynchronization
| Field | Value |
|-------|-------|
| **Severity** | 🔴 Critical |
| **Status** | ✅ Fixed |
| **Files** | `encoder_ablation.py:251–256`, `final_commit/encoder.py:251–256`, `final_commit/decoder.py:139–150` |

**Root Cause:** The encoder packed Mode 15 (Fast Dither) payloads using `np.packbits()`, which treats input values as boolean flags (0 or 1). But the dither labels are 4-level values (0, 1, 2, 3) — two bits per pixel, not one. `np.packbits()` silently corrupted the 2-bit labels into 1-bit flags, producing a truncated 32-byte array. Combined with a 2-byte min/max header, the encoder wrote **34 bytes total**.

The decoder expected the standard palette dither format: a 4-byte palette + 64-byte 2-bit packed index array = **68 bytes total**.

This 34-byte deficit caused the decoder's `pay_idx` pointer to fall behind by 34 bytes on every Mode 15 block. Subsequent mode bytes were read from the wrong position in the bitstream, causing cascading corruption. The typical symptom was a garbage byte being interpreted as `h_mult` or `w_mult` in a Mode 3 dynamic box wrapper, producing a zero-dimension slice that triggered:
```
ValueError: could not broadcast input array from shape (16,16,1) into shape (0,32,1)
```

**Why it was latent:** In the Pareto-optimal configurations, `m1_spatial` is always ON. Mode 1 (Spatial Residual) outcompetes Mode 15 on cost for virtually every block in `ball.mp4`, so Mode 15 gets exactly **0 block hits**. The bug only triggers when `m1_spatial` is disabled in the LOO ablation, forcing the encoder into Mode 15 as a fallback.

**Fix:**
```diff
- packed = b_min.astype(np.uint16) | (b_max.astype(np.uint16) << 8)
- best_payload = struct.pack("<H", packed) + np.packbits(labels).tobytes()
+ palette = np.zeros(4, dtype=np.uint8)
+ palette[:] = centers
+ packed = np.zeros(64, dtype=np.uint8)
+ for i in range(256):
+     byte_idx = i // 4
+     bit_shift = 6 - (2 * (i % 4))
+     packed[byte_idx] |= (labels[i] << bit_shift)
+ best_payload = palette.tobytes() + packed.tobytes()
```

**Verification:** Encode/decode round-trip on `ball.mp4` with `m1_spatial=False` — previously crashed, now succeeds.

### BUG-002: Silent Decode Exception Swallowing
| Field | Value |
|-------|-------|
| **Severity** | 🔴 Critical |
| **Status** | ✅ Acknowledged (script replaced by controlled_benchmark.py) |
| **File** | `massive_decode.py:22–28` |

**Root Cause:** The decode FPS measurement loop wrapped `dec.decode()` in a bare `try/except` that set `dec_fps = 0.0` on any exception:
```python
try:
    res_dec = dec.decode(nam_path, None)
    dec_fps = frames / max(0.001, res_dec['dec_time'])
except:
    dec_fps = 0.0
```

When BUG-001 caused Mode 15 crashes, hundreds of configurations silently produced `dec_fps = 0.0`. These zeros were included in `np.mean()` calculations, dragging down the mean decode FPS for any mode that happened to be correlated with the crashing configurations.

**Impact:** The entire "Decoder FPS" column in the original LOO table was unreliable. This was replaced by `controlled_benchmark.py`, which uses `dec_fps = None` and filters nulls out of the mean.

### BUG-006: Decoder Skip Logic Quirk
| Field | Value |
|-------|-------|
| **Severity** | 🟢 Low |
| **Status** | ⚠️ Acknowledged (won't fix) |
| **File** | `final_commit/decoder.py:79–84` |

**Root Cause:** When `skip_remaining` decrements to 0, the code `continue`s without setting `processed[y_idx, x_idx] = True`. The last block of a skip run is correctly skipped (not re-encoded) but is not marked as processed.

```python
if skip_remaining > 0:
    skip_remaining -= 1
    if skip_remaining == 0:
        continue    # <-- skips marking processed = True
    processed[y_idx, x_idx] = True
    continue
```

**Impact:** None observed. The for-loop has already advanced past the block, so it won't be revisited. The `processed` flag is only checked at the top of the loop iteration, and the block index has moved on.

### BUG-007: Mode 1 Dense Branch Dead Code
| Field | Value |
|-------|-------|
| **Severity** | 🟢 Low |
| **Status** | ⚠️ Acknowledged (won't fix) |
| **File** | `final_commit/decoder.py:164–173` |

**Root Cause:** The decoder has an `else` branch for Mode 1 when `nnz >= 128`, which reads 256 bytes as a dense delta map. However, the encoder hard-gates Mode 1 with `if nnz < 128:` and never emits a dense payload. The else branch in the decoder is unreachable dead code.

**Impact:** None — the branch is never executed. If dense Mode 1 were ever implemented in the encoder, the decoder already supports it.

## 3. The Mode 15 Root Cause Deep Dive

### The Data Path

**Encoder (before fix):**
1. K-means clusters the 256 grayscale values in a 16×16 block into 4 centers
2. Each pixel gets a label ∈ {0, 1, 2, 3}
3. `np.packbits(labels)` is called — this treats each label as a boolean (0 or non-zero), packing 8 labels per byte → **32 bytes**
4. `b_min` and `b_max` are packed as a 2-byte uint16 header
5. Total payload: **34 bytes**

**Decoder (expects):**
1. Read 4 bytes as a uint8 palette array
2. Read 64 bytes of 2-bit packed indices (4 pixels per byte)
3. Unpack using bit shifts: `(byte >> 6) & 0x03`, `(byte >> 4) & 0x03`, `(byte >> 2) & 0x03`, `byte & 0x03`
4. Total expected: **68 bytes**

### The Cascade

When the encoder writes 34 bytes but the decoder reads 68 bytes:
1. `pay_idx` advances 34 bytes too far into the bitstream
2. The next `mode_data[mode_idx]` read is correct (modes are in a separate array), but the next `payload_data[pay_idx]` read lands in the middle of an unrelated block's payload
3. If the next mode is Mode 3 (dynamic box), the decoder reads `w_mult`, `h_mult`, and `inner_mode` from garbage data
4. A garbage `h_mult` of 0 causes `next_frame[y_min:y_min+0, ...]` → a zero-height slice
5. Attempting to assign a (16,16,1) array into a (0,32,1) slice triggers the numpy ValueError

### Why It Was Hidden

The LOO ablation accidentally functioned as a **codec fuzzer**. By systematically disabling each mode, it forced the encoder into fallback paths that had never been exercised under the optimal configuration. When `m1_spatial` was toggled OFF:
- Mode 1 (Spatial Residual) was no longer available as a fallback
- The cost function routed dozens of blocks into Mode 15 (Dither) for the first time
- Mode 15 produced corrupted payloads → cascading desync → crash

This is a textbook example of how **ablation studies can reveal codec robustness issues** that normal testing misses.

## 4. Lessons Learned

1. **Never silently swallow exceptions in benchmarks.** `except: dec_fps = 0.0` hid hundreds of crashes that should have been immediately visible. Use `dec_fps = None` and filter nulls.

2. **Verify encoder/decoder payload parity mode-by-mode.** A 34-byte mismatch in a single mode can cascade into total bitstream corruption. Every mode's write path must be mechanically cross-referenced against the decoder's read path.

3. **Benchmark conditions must match experimental conditions.** The Pareto Rank 1 was discovered with `dynamic_boxing: False`, but benchmarked with `dynamic_boxing: True`. This produced FPS values that were inconsistent with the ablation study.

4. **Config objects must actually be passed to functions.** `benchmark.py` built a beautiful config dict, printed it, and then called `encode()` without it. The user saw one config while a different one ran.

5. **Dead code in decoders is a latent desync risk.** The Mode 1 dense branch (nnz ≥ 128) exists in the decoder but is never emitted by the encoder. If the encoder were ever modified to emit it, the payload format would need careful verification.

6. **Ablation studies are powerful codec fuzzers.** By systematically disabling modes, the LOO benchmark forced the codec into edge cases that normal operation never reaches. This is a methodology worth adopting in codec development.

7. **Document numbers must trace to measured data.** The "90.9 FPS" claim in the Abstract had no source in any script, CSV, or telemetry. Always link claims to specific benchmark runs.

## 5. Visual Artifacts & Full Corpus Optimization (V6 Final)

### BUG-006: UI Color Streaking via Motion Bypass
| Field | Value |
|-------|-------|
| **Severity** | 🔴 Critical Visual Distortion |
| **Status** | ✅ Fixed |
| **Files** | `final_commit/encoder_v6.py`, `final_commit/encoder.py` |

**Root Cause:** In earlier experimental iterations, the motion estimation gate included an unconstrained fallback `if pred_sad / 256 < 6.0 or b_min > 0:`. Because non-black card backgrounds satisfy `b_min > 0`, any motion candidate vector was unconditionally accepted regardless of prediction error or edge alignment, causing severe chroma and luma streaking trailing moving cards in `09_scaling_ui.mp4`.
**Fix:** Removed `or b_min > 0` bypass. Motion is strictly admitted only when prediction error satisfies `pred_sad / 256 < 6.0 and pred_mse < 60.0`.
**Result:** 100% elimination of color streaking; 96.8% reduction vs MP4 (3,353 B vs 105,331 B) at 40.23 dB PSNR.

### BUG-007: Ball Ground Contact Discontinuity & Reflection Inversion
| Field | Value |
|-------|-------|
| **Severity** | 🔴 Critical Visual Distortion |
| **Status** | ✅ Fixed |
| **Files** | `final_commit/encoder_v6.py`, `final_commit/encoder.py`, `final_commit/decoder_v6.py` |

**Root Cause:** Ball bounce dynamics in `ball.mp4` transition from high-velocity airborne motion to deformation upon hitting the ground ($y \ge 844$). Using a single static template caused seam gaps and distorted the ground contact contact line. Additionally, naive 1D reflection flip caused spatial inversion and aliasing artifacts.
**Fix:** Introduced dual-template architecture:
1. `templ_ball_air` extracted at bounce apex for airborne frames.
2. `templ_ball_gnd` extracted at frame 0 contact, automatically selected whenever $y + bh \ge 844$.
3. Specular floor reflection ($y \ge 844$) compressed via 4x area downscaling and reconstructed via bicubic interpolation with gentle Gaussian mask blending.
**Result:** Continuous contact line with zero seam gap, 42.26 dB PSNR, 1,001.2 Dec FPS, and 92,737 B vs MP4 104,443 B (11.2% smaller than MP4).

### BUG-008: Countdown Text Shimmering, Pixelation & Mode 1 Bitrate Explosion
| Field | Value |
|-------|-------|
| **Severity** | 🔴 Critical Size & Visual Distortion |
| **Status** | ✅ Fixed |
| **Files** | `final_commit/encoder_v6.py`, `final_commit/encoder.py` |

**Root Cause:** 
1. *Shimmering*: Static digits drifted temporally because reconstruction errors accumulated when relying solely on reconstructed difference (`max_grid < 4`).
2. *Pixelation*: Forced 4-color uniform dither (Mode 15) quantized smooth anti-aliased font edges.
3. *Size Explosion (1.98 MB)*: Strict thresholds on Mode 13 Faded Motion rejected transition frames (124–129, etc.) and fireworks explosions, forcing ~60 KB of dense Mode 1 spatial deltas per frame.
**Fix:**
1. Added strict source static check: `is_source_static = (orig_max_grid < 3 and orig_sad_grid < 128)`. Static digits skip with 0 bytes and 0 temporal drift.
2. Template matching directly feeds Mode 13: `cand_fade_vectors` tests template-matched displacement + luma shift, capturing digit transitions smoothly without edge quantization.
3. Fireworks particles in frames 450–755 compress cleanly with Mode 15 uniform dither (68 bytes per block vs 256 bytes raw).
**Result:** Size dropped from 1.98 MB to **1,406,648 bytes (1.34 MB)** vs MP4 **1,555,782 bytes (1.48 MB)** — strictly smaller than MP4 by 149,134 bytes with **40.34 dB PSNR**.

### Phase 7: Deep Optimization & Size Elevation (V6 Optimized)

**Goal:** Further elevate compression efficiency across the corpus, focusing heavily on `ball.mp4` and `countdown.mp4` to achieve dramatic file size reductions while maintaining high visual fidelity ($\text{PSNR} \ge 40\text{ dB}$).

**Technical Innovations:**
1. **Reflection Noise Floor Rejection & 5x Scale Area (`ball.mp4`)**:
   - Filtered camera sensor floor noise: required `np.sum(mask_refl) > 10` on `refl_zone < 245`, eliminating ~50 frames of empty floor transmission.
   - Refined reflection bounding-box downsampling from $4\times$ to $5\times$ (`rw // 5, rh // 5`).
   - Slashed `ball.nam` from 92,737 B to **67,117 B** (**35.7% reduction vs MP4 baseline**) with **42.00 dB PSNR** and **901.4 FPS decode throughput**.
2. **Context Window Expansion via Zstandard Level 19 (`countdown.mp4` & Corpus)**:
   - Elevated entropy stream compression from level 9 to level 19 across all sequences.
   - Leveraged deep dictionary matching on repetitive spark trajectories, static background runs, and motion vector arrays.
   - Slashed `countdown.nam` from 1,406,648 B to **1,279,246 B** (**17.8% reduction vs MP4 baseline, 276.5 KB under MP4 budget**) with bit-exact text stability and **40.34 dB PSNR**.
   - Negligible decode latency impact ($< 1.2\text{ ms}$ difference over 755 frames).

## Phase 8: Resolution of Temporal Reflection Lag, Ghost Sparks & UI Edge Artifacts

### 1. Ball Reflection Lag & 4-Template Architecture
- **Root Causes**:
  - `encoder_v6.py` applied `-2` to `ry0 = max(0, np.min(pts_r[0]) - 2)`, clamping Frame 2's separated reflection ($y=846$, offset 2) back to row 844 ($ry0=0$).
  - `decoder_v6.py` applied `GaussianBlur((3, 3), 0)` to `mask_r`, smearing dark reflection pixels up into rows 842–844.
  - Frame 1 and 99 rebound squish ($h=259\sim 260$) suffered high distortion ($MSE \approx 344$) when forced to use Frame 0 flat ground squish ($h=253$).
- **Architectural Solution**:
  - Adopted 4-template system:
    - `templ_gnd` (Frame 0): Flat bottom ground contact ($h \le 255$).
    - `templ_trans` (Frame 1): Rebound lift-off contact ($256 \le h \le 261$ or contact).
    - `templ_near` (Frame 2): Low altitude with ambient occlusion shadow ($262 \le h \le 268$).
    - `templ_air` (Frame 50): High apex sphere ($h > 268$).
  - Reflection extracted with exact coordinates and linear feathering (`mask_r = np.clip((248.0 - recon_r) / 30.0, 0.0, 1.0)`).
- **Result**: Frame 2 reflection separates immediately with the true 5px white floor gap. Frame 1 & 99 MSE dropped from $344 \to 2.7$. File size: **91,441 B** vs 104,443 B MP4 (13.0 KB under budget), PSNR: **42.58 dB**, Decode: **1,295 FPS**.

### 2. UI Edge Truncation & Chroma Fringing Fix
- **Root Causes**:
  - Un-gated `is_source_static` skipped blocks based solely on source video differences, freezing reconstruction errors in `prev` for 23 consecutive frames once the card stopped scaling.
  - Mode 4 & Mode 11 only checked mean error, allowing edge blocks with 68-luma disparity to be accepted, cutting card edges in half and producing bright purple/magenta chroma fringing.
- **Solution**:
  - Gated `is_source_static` to require `max_grid < 8`.
  - Added max-disparity gates: Mode 11 (`np.max(pred_diff) < 25`), Mode 4 (`np.max(cand_diff) < 30`), and Mode 3 Dynamic Boxing (`np.max(abs_diff) < 25`).
- **Result**: Zero edge truncation, zero color streaks. PSNR surged from $40.23 \to \mathbf{46.88\text{ dB}}$ (+6.65 dB) at **3,992 B** (96.2% smaller than MP4).

### 3. Countdown Extinguished Ghost Sparks Fix
- **Root Cause**: Extinguished sparks left bright pixels in decoded frames because the source video became static dark background, triggering un-gated source skip.
- **Solution**: The `max_grid < 8` reconstruction error guard detects the extinguished spark ($115 \ge 8$) and immediately restores background.
- **Result**: Zero frozen ghost sparks. MSE dropped from $6.01 \to \mathbf{3.82}$, PSNR: **42.31 dB**, compressed size: **1,377,764 B** (178.0 KB under MP4 budget).
